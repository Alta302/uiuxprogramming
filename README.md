# 신선노트 (FreshNote)

냉장고 속 식재료의 소비기한을 확인하고, 먹은 재료를 구분할 수 있도록 돕는 서비스입니다.

## 9주차 추가·수정한 기능

- 식재료 등록 단계를 하나의 폼으로 묶고, 확인 화면의 제출로 보관 목록에 저장하도록 변경했습니다.
- 식재료 이름과 보관 메모에 글자 수·조건 충족 안내를 추가했습니다. 잘못된 값을 수정하면 오류 문구도 해제됩니다.
- ‘보관 메모 남기기’를 선택할 때만 메모 입력란을 표시합니다. 해제하면 입력란을 숨기고 비활성화하여 제출값에서 제외합니다.
- 저장 중에는 진행 문구를 표시하고 폼 조작과 중복 제출을 막습니다. 성공하면 완료 화면을 표시하고, 실패하면 입력값을 유지한 채 다시 저장할 수 있습니다.
- 보관 목록과 메모, 소비 완료 상태를 브라우저에 저장하여 새로고침해도 유지합니다. 실제 알림은 발송하지 않습니다.

## 입력 조건

| 항목 | 조건 |
| --- | --- |
| 식재료 이름 | 필수, 앞뒤 공백을 제외하고 1~20자 |
| 소비기한 | 필수, 오늘 또는 이후의 날짜 |
| 알림 시점 | 3일 전·1일 전·당일 중 선택, 알림 예정일이 오늘보다 이전이면 수정 |
| 보관 메모 | 메모 남기기를 선택한 경우에만 필수, 앞뒤 공백을 제외하고 2~80자 |

글자 수는 입력한 공백을 포함해 표시하고, 유효성 검사는 앞뒤 공백을 제외한 값으로 수행합니다.

## 확인 순서

1. 등록을 시작하고 빈 값으로 다음을 눌러 오류 안내와 첫 오류 입력창으로의 초점 이동을 확인합니다.
2. 공백만 있는 이름과 지난 소비기한을 입력한 뒤 올바르게 수정하여 오류가 해제되는지 확인합니다.
3. 알림 시점을 선택하지 않거나 이미 지난 알림 날짜를 선택해 안내를 확인한 뒤 수정합니다.
4. 메모 남기기를 선택하고 빈 값·한 글자를 입력합니다. 두 글자 이상으로 수정해 글자 수와 조건 충족 안내를 확인합니다.
5. 체크를 해제하면 메모 영역이 숨겨지고 입력이 비활성화되는지 확인합니다. 다시 선택하면 작성한 메모가 유지되는지 확인합니다.
6. 확인 화면에서 이름·날짜·선택한 알림·메모를 확인하고, 이전 단계에서 수정한 내용이 반영되는지 확인합니다.
7. 저장을 눌러 진행 문구와 버튼 비활성화, 완료 안내를 확인합니다. 연속 제출해도 목록에 한 번만 저장되는지 확인합니다.
8. 다시 시작을 눌러 입력값·체크 상태·글자 수·오류·저장 안내·버튼 상태가 초기화되는지 확인합니다. 기존 보관 목록은 유지됩니다.
9. 보관 목록에서 소비 완료·되돌리기를 조작하고 새로고침한 뒤에도 목록과 메모, 소비 상태가 유지되는지 확인합니다.

## 실패 처리와 확인 결과

브라우저 저장이 차단되거나 저장 공간이 부족하면 실패 안내와 ‘다시 저장하기’ 버튼을 표시합니다. `script.js`의 `saveInventory()`에서 저장하며, `handleRegistrationSubmit()`의 `catch`에서 입력값을 유지하고 재시도 상태로 복구합니다. 기존 저장 데이터가 올바르지 않은 경우에는 `readStoredInventory()`에서 감지하여 덮어쓰지 않습니다.

2026-11-09, 로컬 Chromium의 1100·768·390·320px 화면에서 위 순서를 확인했습니다. 저장소 쓰기에 오류를 발생시켜 실패 후 입력 유지와 재시도를 확인했고, 정상 저장·중복 방지·모바일 조작도 통과했습니다. 기존 탭·알림 미리보기·이메일 신청 및 주소 수정도 정상 동작했습니다.
