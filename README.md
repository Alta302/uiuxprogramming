# 신선노트 (FreshNote)

냉장고 속 식재료의 소비기한을 확인하고, 먹은 재료를 구분할 수 있도록 돕는 서비스입니다.

## 10주차 추가·수정한 기능

- 주요 메뉴를 `nav` 안의 `ul`·`li`로 구성했습니다. 현재 목적지는 배경과 밑줄로 구분하고 `aria-current="location"`을 적용합니다. 주소의 해시를 기준으로 처음 접속·메뉴 이동·새로고침·뒤로/앞으로 가기 때 표시를 갱신합니다.
- 768px 이하에서는 ‘메뉴 열기·닫기’ 버튼을 사용합니다. 실제 메뉴 표시와 버튼 문구, `aria-expanded`가 함께 바뀝니다. 목적지를 선택하면 메뉴를 닫고 해당 영역 제목으로 초점을 옮깁니다. Escape로 닫을 수도 있습니다.
- 보관 목록에 전체·보관 중·소비 임박·소비 완료 필터를 추가했습니다. 선택한 버튼의 색상·밑줄·`aria-pressed`, 실제 목록과 결과 수가 함께 바뀝니다.
- 저장된 식재료가 하나도 없는 경우에는 등록을 안내하고, 선택 조건에만 결과가 없는 경우에는 다른 필터를 안내합니다. 소비 완료·되돌리기 후에도 선택한 조건과 결과 수를 갱신합니다.
- 등록 완료 화면의 ‘보관 목록 확인하기’는 전체 필터로 전환하여 새 항목을 보여 주고, 주소와 현재 메뉴도 보관 목록으로 바꿉니다. 기존 입력 검증·저장·실패 후 재시도·메모·새로고침 후 유지 기능을 함께 사용할 수 있습니다.

### 메뉴별 목적지

| 메뉴 | 목적지 | 확인할 내용 |
| --- | --- | --- |
| 서비스 소개 | `#about` | 서비스 목적과 소개 이미지 |
| 주요 기능 | `#features` | 소비기한 관리·알림·레시피 탭 |
| 이용 방법 | `#steps` | 식재료 관리 이용 순서 |
| 알림 미리보기 | `#reminder-preview` | 식재료 이름으로 알림 문구 체험 |
| 식재료 등록 | `#registration` | 입력·확인·저장 단계 |
| 보관 목록 | `#inventory` | 저장한 식재료와 필터, 소비 완료·되돌리기 |
| 알림 신청 | `#subscribe` | 이메일 신청 및 주소 수정 시연 |

### 필터 기준

| 필터 | 표시 항목 |
| --- | --- |
| 전체 | 저장한 모든 식재료 |
| 보관 중 | 소비 완료하지 않은 식재료, 기한이 지난 항목도 포함 |
| 소비 임박 | 보관 중이며 소비기한이 오늘부터 3일 이내인 식재료 |
| 소비 완료 | 소비 완료로 변경한 식재료 |

소비기한은 브라우저의 오늘 날짜를 기준으로 계산하며, 각 목록은 소비기한이 가까운 순으로 표시합니다. 결과 수는 전체 저장 개수와 현재 표시 개수를 함께 안내합니다. 새로고침하면 필터는 ‘전체’로 시작하고 저장한 목록과 소비 상태는 유지됩니다.

### 10주차 확인 순서

1. 주요 메뉴를 차례로 눌러 이름에 맞는 영역으로 이동하는지 확인합니다. 주소 끝의 해시와 현재 메뉴 표시를 비교하고 새로고침·뒤로 가기·앞으로 가기에서도 확인합니다.
2. 식재료 등록 메뉴에서 이름·소비기한·알림·메모를 입력하고 확인 화면에서 저장합니다. ‘보관 목록 확인하기’를 눌러 새 항목, 전체 필터, 보관 목록 메뉴의 선택 표시를 확인합니다.
3. 전체·보관 중·소비 임박·소비 완료를 바꾸며 선택 버튼과 카드 내용·결과 수를 비교합니다. 오늘부터 3일 이내의 재료와 4일 이후 재료로 소비 임박 조건을 확인합니다.
4. 보관 중 필터에서 ‘소비 완료’를 누르면 해당 카드가 사라지는지 확인합니다. 소비 완료 필터에서 되돌리고 새로고침하여 상태가 유지되는지 확인합니다.
5. 데이터가 없는 새 브라우저에서는 등록 안내가 나오는지, 데이터가 있는 상태에서 결과 없는 필터를 고르면 다른 조건 선택 안내가 나오는지 비교합니다.
6. 768px 이하에서 메뉴를 여러 번 열고 닫고, 목적지 선택 후 닫힘을 확인합니다. 769px 이상으로 넓혔다가 다시 줄여도 버튼과 메뉴 상태가 일치하는지 확인합니다. 모바일에서도 등록 → 목록 → 필터 흐름을 반복합니다.
7. 기존 탭·알림 미리보기·이메일 신청 및 주소 수정, 아래 입력 검증·저장 실패 후 재시도 순서를 확인합니다.

2026-11-16, 로컬 Chromium의 1100·768·390·320px 화면에서 메뉴 이동 → 등록 → 목록 → 필터 흐름을 확인했습니다. 해시 주소 직접 접속·새로고침·뒤로/앞으로 가기, 768/769px 경계 전환, 메뉴 닫기·Escape, 필터별 카드·결과 수·빈 결과 안내를 통과했습니다. 소비 임박의 오늘·3일·4일·지난 날짜 경계와 기존 저장 데이터도 확인했습니다. 입력 오류·메모 표시·저장 실패 후 재시도·중복 제출 방지·소비 상태 유지 및 기존 탭·미리보기·이메일 조작을 통과했고, JavaScript 실행 오류와 가로 넘침은 없었습니다. 잘못된 저장 데이터는 덮어쓰지 않고 읽기 실패를 안내합니다.

## 9주차 추가·수정한 기능

- 식재료 등록 단계를 하나의 폼으로 묶고, 확인 화면의 제출로 보관 목록에 저장하도록 변경했습니다.
- 식재료 이름과 보관 메모에 글자 수·조건 충족 안내를 추가했습니다. 잘못된 값을 수정하면 오류 문구도 해제됩니다.
- ‘보관 메모 남기기’를 선택할 때만 메모 입력란을 표시합니다. 해제하면 입력란을 숨기고 비활성화하여 제출값에서 제외합니다.
- 저장 중에는 진행 문구를 표시하고 폼 조작과 중복 제출을 막습니다. 성공하면 완료 화면을 표시하고, 실패하면 입력값을 유지한 채 다시 저장할 수 있습니다.
- 보관 목록과 메모, 소비 완료 상태를 브라우저에 저장하여 새로고침해도 유지합니다. 실제 알림은 발송하지 않습니다.

## 입력 조건

| 항목 | 조건 |
| --- | --- |
| 식재료 이름 | 필수, 앞뒤 공백을 제외하고 1~20자 |
| 소비기한 | 필수, 오늘 또는 이후의 날짜 |
| 알림 시점 | 3일 전·1일 전·당일 중 선택, 알림 예정일이 오늘보다 이전이면 수정 |
| 보관 메모 | 메모 남기기를 선택한 경우에만 필수, 앞뒤 공백을 제외하고 2~80자 |

글자 수는 입력한 공백을 포함해 표시하고, 유효성 검사는 앞뒤 공백을 제외한 값으로 수행합니다.

## 확인 순서

1. 등록을 시작하고 빈 값으로 다음을 눌러 오류 안내와 첫 오류 입력창으로의 초점 이동을 확인합니다.
2. 공백만 있는 이름과 지난 소비기한을 입력한 뒤 올바르게 수정하여 오류가 해제되는지 확인합니다.
3. 알림 시점을 선택하지 않거나 이미 지난 알림 날짜를 선택해 안내를 확인한 뒤 수정합니다.
4. 메모 남기기를 선택하고 빈 값·한 글자를 입력합니다. 두 글자 이상으로 수정해 글자 수와 조건 충족 안내를 확인합니다.
5. 체크를 해제하면 메모 영역이 숨겨지고 입력이 비활성화되는지 확인합니다. 다시 선택하면 작성한 메모가 유지되는지 확인합니다.
6. 확인 화면에서 이름·날짜·선택한 알림·메모를 확인하고, 이전 단계에서 수정한 내용이 반영되는지 확인합니다.
7. 저장을 눌러 진행 문구와 버튼 비활성화, 완료 안내를 확인합니다. 연속 제출해도 목록에 한 번만 저장되는지 확인합니다.
8. 다시 시작을 눌러 입력값·체크 상태·글자 수·오류·저장 안내·버튼 상태가 초기화되는지 확인합니다. 기존 보관 목록은 유지됩니다.
9. 보관 목록에서 소비 완료·되돌리기를 조작하고 새로고침한 뒤에도 목록과 메모, 소비 상태가 유지되는지 확인합니다.

## 실패 처리와 확인 결과

브라우저 저장이 차단되거나 저장 공간이 부족하면 실패 안내와 ‘다시 저장하기’ 버튼을 표시합니다. `script.js`의 `saveInventory()`에서 저장하며, `handleRegistrationSubmit()`의 `catch`에서 입력값을 유지하고 재시도 상태로 복구합니다. 기존 저장 데이터가 올바르지 않은 경우에는 `readStoredInventory()`에서 감지하여 덮어쓰지 않습니다.

2026-11-09, 로컬 Chromium의 1100·768·390·320px 화면에서 위 순서를 확인했습니다. 저장소 쓰기에 오류를 발생시켜 실패 후 입력 유지와 재시도를 확인했고, 정상 저장·중복 방지·모바일 조작도 통과했습니다. 기존 탭·알림 미리보기·이메일 신청 및 주소 수정도 정상 동작했습니다.
